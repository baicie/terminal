# 人工验收清单（自动化无法替代的部分）

> 创建日期：2026-10-28
> 适用源码：fingerprint `04bb5973…`（Phase 6.105 自动化证据全绿之后的同一工作树）
> 用途：下面是自动化覆盖不到、必须由人在真实硬件上执行的验收项。每完成一项，把结果、日期与观测到的异常追加到 `docs/issue.md` 的 Issue #58（macOS 人工输入）或 #39/#21（Windows/Linux/串口）条目里。

## 准备：用发布形态的产物做人工验收

自动化证据用的是 `VITE_TERMINAL_SMOKE_BUILD=1` 的插桩产物（包体稍大、带 smoke 入口）。人工验收应使用**不含插桩**的产物，否则测的不是用户拿到的东西：

```bash
VITE_TERMINAL_SMOKE_BUILD= pnpm tauri build --no-bundle
./src-tauri/target/release/terminal
```

## 1. macOS 物理键盘：重叠输入 30 轮

- 步骤：打开一个 Local 终端，快速交替键入 `a` `s` `d` 共 30 轮（90 个字符），中途不要停顿校正。
- 预期：终端回显恰好是 `asd` 重复 30 次；不出现重复字符、丢字符、顺序错乱。
- 记录：复制整行回显内容。
- 关联：Issue #26 / #58；自动化覆盖了 `xterm → 前端 FIFO` 的协议层，但物理键盘的 `keydown → input` 时序只有真机才有。

## 2. 中文 IME 组合输入

- 步骤：切到中文输入法，键入 `nihao` 选「你好」，再输入中文逗号与句号，最后回车。
- 预期：组合过程中不向 PTY 逐字写入；选词后一次性写入「你好」；标点为全角；回车执行一次，不触发两次。
- 记录：输入过程中的终端内容与最终命令行。

## 3. Option / dead key（非美式键盘）

- 步骤：`Option+e` 后按 `e`（应为 `é`）；`Option+u` 后按 `u`（应为 `ü`）；美式键盘再试 `Option+5`（应为 `ﬁ`）。
- 预期：每个组合输出一个字符，无重复、无丢字符。
- 关联：Issue #123（WKWebView Option-as-Meta 双发已修，需真机确认）。

## 4. 编辑器与信号（自动化已覆盖，建议抽查一次）

- `vim file` 进入、编辑、`:wq` 退出；`nano file` 同理；`Ctrl+C` 中断 `sleep 20`；拖动窗口改变大小后执行 `stty size`。
- 预期：编辑内容正确、无花屏；信号只中断一次；`stty size` 与新窗口尺寸一致。

## 5. 合盖休眠 / 唤醒

- 步骤：连接一台远端主机并保持前台，合盖 30 秒后开盖。
- 预期：会话在合理时间内自动恢复，或至少给出可一键重连的 retryable 错误；恢复后输出不与其他会话串行、不缺字节。
- 关联：Issue #113/#117；自动化只覆盖应用内恢复协议，真实合盖的行为必须实测。

## 6. 网络切换（Wi-Fi ↔ 蜂窝 / VPN 连接与断开）

- 步骤：远端会话保持连接，切换网络或在 VPN 上断开/恢复。
- 预期：不进入不可恢复的终态；恢复后能继续输入；重连次数有限且退避可见。

## 7. Windows 实机

- OpenSSH Agent 与 Pageant 两种身份来源各连一次（参见 `docs/release-readiness.md` 的实机矩阵）。
- ConPTY 本地终端：输入、resize、Ctrl+C。
- 快捷键：`Ctrl+Shift+\` 触发垂直分屏，且不覆盖系统快捷键。

## 8. Linux 桌面与串口硬件

- Linux：bash 与 zsh 的本地 PTY 输入、resize、`Ctrl+C`。
- 串口：真实设备枚举、精确写入、主动断开与运行中拔线后的会话清理（参见 Issue #21/#39）。

## 完成后如何闭环

1. 在 `docs/issue.md` 对应条目追加「日期 + 观测结果 + 异常」。
2. 如果发现缺陷，按 `docs/release-readiness.md` 的顺序处理：先改源码、再重建插桩产物、**重新固定复核哈希**，然后重采 `docs/verification` 里的证据（顺序颠倒会让刚采到的证据立刻作废）。
3. 全部通过后，更新 `docs/release-readiness.md` 的实机矩阵表与 `AGENTS.md` 的当前关键问题表。
