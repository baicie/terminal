## 1. 与 Tabby 并行使用的安全切换

不建议某天直接停用 Tabby。数据丢失的风险不在 Terminal 本身，而在「以为两边的是同一份」。

### 1.1 切换前（一次性）

1. **备份 Terminal 的数据库**：设置 → 存储 → 导出。确认导出文件里**不含**密码或私钥
   （文件应是 JSON，搜索 `"password"` 与 `BEGIN` 应无匹配）。
2. **记录当前主机清单**：Hosts 页面截图或复制列表，作为对照组。
3. **不要在两边同时编辑同一台主机**。Terminal 与 Tabby 各自维护主机数据，
   没有同步机制 —— 一边改了密码，另一边仍是旧的。

### 1.2 并行期（建议 7 天）

| 阶段 | Terminal 承担 | Tabby 保留 |
| --- | --- | --- |
| D1–D2 | 本地 shell、只读 SSH | 所有写操作、SFTP 上传 |
| D3–D5 | 本地 shell、SSH（含 Jump）、SFTP 下载 | 需要上传/覆盖的操作 |
| D6–D7 | 全部日常操作 | 仅备用，不主动打开 |

### 1.3 回退路径

任何时候需要回退：Tabby 的数据未被修改，直接打开即可。Terminal 侧不需要清理
—— 它的数据在独立目录，不影响 Tabby。

**不要**为了让两边一致而手工同步数据库文件。那是两套 schema。

## 2. 备份与恢复

### 2.1 需要备份的三样东西

| 项 | 位置 | 说明 |
| --- | --- | --- |
| 主机与设置 | `terminal.db`（应用数据目录） | 明文，不含秘密 |
| Vault | `vault.json`（同目录） | 加密，密码不在其中 |
| 已知主机指纹 | `terminal.db` 的 `known_hosts` 表 | 丢失后首次连接需重新信任 |

### 2.2 备份步骤

```
设置 → 存储 → 导出          （主机/片段/工作区，不含秘密）
应用数据目录 → 复制 terminal.db 与 vault.json
```

**两者必须一起备份。** 只备份 `terminal.db` 会得到「有引用但没有秘密」的主机 ——
恢复后每台主机都提示需要重新输入凭据。

### 2.3 恢复步骤

1. 关闭应用（确保没有进程持有文件锁）；
2. 把 `terminal.db` 与 `vault.json` 放回数据目录；
3. 启动应用 —— `db_recovery` 会检测迁移标记，若有部分迁移会自动恢复快照；
4. 用原 Vault 主密码解锁；
5. 验证：任选一台主机连接，确认无需重输凭据。

### 2.4 恢复后必须验证的四件事

- [ ] 主机数量与备份前一致
- [ ] 收藏与分组仍在
- [ ] 至少一台主机能直接用已存凭据连接（不需要重输）
- [ ] Workspace 布局与标签恢复

## 3. 真实 GUI 最小验收清单

以下每条都需要真实鼠标/键盘操作，无法自动化。**逐条勾选，未做即留空。**

- [ ] 卡片「⋯」→ Edit，对话框显示该主机的现有值

### 3.2 Vault

- [ ] 新装环境保存带密码的主机 → 出现「需要创建 Vault」面板，**已输入的密码仍在**

- [ ] 导入含 `IdentityFile` 的主机 → 连接时提示需要绑定密钥（不是密钥解析错误）
- [ ] 在该主机的对话框里看到密钥文件路径提示 → 粘贴密钥 → 保存 → **连接成功**
- [ ] 导入含 `ProxyJump` 的配置 → 确认跳板机也被导入 → **连接成功**

## 6. 阻断分级

| 级别 | 定义 | 例子 |
| --- | --- | --- |
| **P0** | 数据丢失、安全失效、应用无法启动 | 保存后凭据消失；Vault 被绕过；白屏 |
| **P1** | 日常操作无法完成，但有绕行 | 某台主机连不上；SFTP 上传失败；IME 输入错乱 |
| **P2** | 不方便，不影响完成 | 布局别扭；某处文案不清 |
| **P3** | 观感问题 | 图标不对齐 |

**回退 Tabby 的判定**：任一 P0，或同一天遇到 2 次以上 P1，即记录为「被迫回退」，
并在原因栏写清是哪一条。

## 7. 7 天数据的最终判定规则

全部满足才算通过：

| 条件 | 阈值 |
| --- | --- |
| 未解决 P0 | **0** |
| 阻断日用的 P1 | **0** |
| 被迫回退 Tabby | **0 次** |
| 常用 SSH 流程完整 | 密码/密钥/Agent/Jump 各至少成功一次 |
| SFTP 流程完整 | 上传/下载/覆盖各至少成功一次 |
| 本地 shell 与多会话稳定 | 无异常退出 |
| 重启后数据正确 | §2.4 四项全部勾选 |
| 主观效率 | 自评 ≥ 4/5 |

**任何一项不满足，`TABBY_REPLACEMENT_READY` 保持 NO。** 不因为「只差一点」而放宽。
