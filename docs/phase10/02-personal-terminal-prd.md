# Phase 10 — 个人日用终端 PRD

## 定位转变

从"广泛的管理平台"收敛为**单开发者每天使用的终端**。
判据不是功能数量，而是：打开就能干活，且不需要为了日常操作再开 Tabby。

## 首要原则

Terminal-first · Local-first · Keyboard-first · Reliability-first

## 用户与场景

- 单人开发者，一天内反复连接 5–20 台机器，大量使用本地 shell。
- 痛点排序（据本阶段审计）：凭据安全 > 粘贴误执行 > 搜索找不到主机 > 改键丢失 >
  UI 层级混乱。

## 本期范围

| 里程碑 | 内容 | 状态 |
| --- | --- | --- |
| M1 | 凭据边界与本地数据完整性 | 代码完成，见 ADR |
| M2 | 主机搜索、Quick Connect、快捷键持久化、安全粘贴 | 代码完成 |
| M3 | Terminal-first 布局与启动 | 代码完成 |
| M3 扩展 | OpenSSH 导入 | 解析+计划完成，UI 未接 |
| M4 | 个人日用 QA 构建与 Scorecard | 见验收文档 |

## 明确不做

- 插件平台、云协作、第二套终端模拟器、第二套 UI 框架；
- 为重构而重构；
- 用扩大测试数量代替产品完成度。

## 成功判据（可测量）

见 `06-daily-driver-acceptance.md` 的 Scorecard。核心三条：

1. 首个本地 Shell 可输入时间（现状待测）；
2. 100 台主机下命令面板能命中任意一台（已由测试保证）；
3. 连续使用一天的阻断次数（需真实使用数据）。
